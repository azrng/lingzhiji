# T45 quiz 引擎判对口径修复（待拍板）

## 目标

修复 M2 题型改版遗留的引擎判对 bug：c2w/listen 题答对恒被判错。**待用户拍板后实施**；登记原因：该 bug 使线上计分/FSRS 失真、污染 T43 试玩数据、并使 balance-sim 学习线数字失真（正式平衡复跑的数据基础不可信）。

## 证据（2026-11-18 复核 94b45e1 balance-sim 修复时发现）

- `src/game/quiz.ts:95` `answer()` 对所有非 spell 题判 `correct = choice === q.meaning`；`src/game/quiz.ts:120-123` `confirm()` 的 `isCorrect` 同口径——只对 w2c（选项=释义）成立
- M2 后 c2w/listen 的 opts 是英文单词（`src/game/question-types.ts` `buildWordOptions`），meaning 是中文释义 → 答对单词恒判错，该两类题无论答什么都计 0 分 + FSRS 记失败
- UI 是 kind-aware 的（`src/components/QuizModal.tsx:267`、`:298` 按 kind 判 word）→ 玩家看到「答对」反馈，计分与复习调度按错记，感知与数值背离
- 测试盲区：`quiz.test.ts:157/189` 满分用例对所有非 spell 题传 `q.meaning`，仅当全部题目为 w2c 时成立（sessions<2 时题型池只有 w2c）；无用例让 c2w/listen 走过真实 `answer()`，故 vitest 150 绿测未拦截
- sim 侧（94b45e1 已修的分流作答）传 `q.word` 想答对，被引擎恒判错 → c2w/listen 实际正确率恒 0，学习线被压低（quick 复跑学习起步 192.5 vs M2 前 113 游戏日，方向一致；叠加 M1/M2 机制变化未单独归因）

## 修复方案（拍板后执行，改动面小）

1. `quiz.ts` `answer()` 与 `confirm()` `isCorrect` 两处判对按 kind 分流：w2c→`choice === q.meaning`；c2w/listen→`normalize(choice) === normalize(q.word)`（与 QuizModal:267 同口径）；spell 分支不动
2. 回归用例：构造 c2w/listen 会话走真实 dispatch——答对判 correct、计分入 `score`、FSRS 不记失败；答错路径保持
3. 验证：typecheck + vitest 全绿 + `npm run sim:quick` 复跑对照学习线数字（与 94b45e1 后 quick 报告对比）
4. 单独提交，不与其他任务混入
