# 时间解耦与节奏压缩需求（T49）

## 1. 背景与目标

用户真实试玩两天的结论：等待替代了游玩。现设计把游戏日与现实日软锚定（晨露/道心/地力透支），灵植成熟 15~60 游戏日，玩家实际只能一天一天磨；多推游戏日虽可用，但带惩罚（事件率减半、收获修为减半），体验上「等于告诉你别用」。

产品定位已反转（PRD §1，7712a9c）：种植灵植是游戏主体，好玩优先。本需求把经营线的时间从现实日解耦出来：

- **入定**：玩家主动快进 N 个游戏日，灵田照常生长，一茬（种→长→收→卖）在一个 session 内完整走完
- **节奏压缩**：生长期整体缩短，匹配分钟级 session
- **删惩罚式多推**：地力透支机制整体移除
- **测验奖励锚现实日**：防连推刷奖励；SRS 本就锚现实日（quiz.ts 注入 `realDay.today`），零冲突

不做本需求 = 「15 天谁等得了」的核心抱怨保留，后续所有种田深度（轮作/物候/委托/炼丹）都被 15~60 天周期压制而无法体验。

## 2. 范围

### 包含

1. 新动作 MEDITATE（入定）：选跨度（1~N 天，上限当月末）→ 逐日批量结算 → 结果摘要面板
2. 生长期压缩：六种灵植 days 全表调整
3. 删除地力透支：`gamesToday`、`DIMINISH_*` 常量、事件率/修为减半分支、TopBar「地力透支」标签、debug 面板相关项
4. 测验门控解绑与奖励改锚：END_DAY 不再要求任务堂完成；测验资源奖励每现实日 1 次
5. 出关预演：入定前联动预览（推进至第几日/成熟情况/缺水风险）
6. 明日预告：出关摘要尾部一行钩子文案
7. 存档迁移 v4→v5：生长进度折算、`gamesToday` 删除、测验锚改现实日

### 不包含（后续批次）

- 品阶重定义（药童→宗师）、删吐纳——身份包，另行立项
- 离线闭关收益（离线不推进维持现状）、炼丹坊、逐株收获 roll 演出、M4 灵雨挑战
- 现实日锚的晨露/道心连胜/修行日历——保留不动（它们是奖励不是枷锁）

## 3. 用户与页面

- 用户：单人本地玩家
- 页面：主界面 ActionPanel「入定」按钮（坊市右侧）+ 入定弹层（已落沉淀型原型：`src/components/MeditateModal.tsx` + `src/game/meditate.ts` Fake，待接引擎）
- 弹层四态：正常（滑条+预演+执行）/ 出关结果（逐日摘要+明日预告）/ 月末拦截（quota 未结算）/ 存档异常

## 4. 核心业务规则

### 4.1 入定（MEDITATE，0 AP）

| 规则 | 内容 |
|---|---|
| 前置 | `phase = 'day'`；月末定额未结算时拒绝（`QUOTA_PENDING`）——月末是唯一中断点 |
| 跨度 | 1 天 ~（30 − 当日月序）天；快捷档：1/3/7 天、「至下次成熟」（最早成熟田剩余天数） |
| 结算 | 逐日复用现有 endDay 五步管线（事件→生长→缺水→月末→推进），不新建第二套结算逻辑 |
| 中断 | 推进到月末（monthDay=30）自动出关，置 `phase='quota'` 进定额结算 |
| 突破 | 逐日结算中自然触发的境界突破照常结算并入摘要，不打断入定 |
| 干旱 | 入定期间无法浇灌：`!wateredToday` 照常累计 dryStreak，达 3 减产一次并清零重计——这是入定的核心取舍点 |
| 日志 | 多日结算折叠为汇总条目（入定 N 天：事件 X 起/成熟 Y 田/减产 Z），不逐日刷穿 50 条环形日志 |
| 预演 | 滑条联动、确定性预览：推进至第几日、成熟田、缺水风险行；预演不落盘 |

### 4.2 生长期压缩（÷3 取整）

| 灵植 | 现 days | 新 days | 说明 |
|---|---|---|---|
| 青灵草 | 15 | 5 | 首茬基准：5 分钟一茬 |
| 凝露花 | 20 | 7 | |
| 紫云芝 | 30 | 10 | |
| 赤髓参 | 35 | 12 | |
| 龙血藤 | 50 | 17 | |
| 九叶莲 | 60 | 20 | |

- 功法 Lv2「生长期 −1」照旧（最低 1 天）；物候/轮作/特质规则不变
- **配套重校（balance-sim 强制）**：月定额 15 株当量、灵草售价/种子价、事件对生长期的相对权重、通关时长目标从「60–90 现实日」改为「N session / 游戏日口径」——具体由 sim 报告定，不拍脑袋

### 4.3 删地力透支

- 删 `realDay.gamesToday` 字段、`DIMINISH_EVENT_CHANCE`/`DIMINISH_EXP_MULT` 常量、engine/farming 的减半分支、TopBar「地力透支」标签及首次说明日志、debug 面板「跳现实日」中依赖 gamesToday 的部分
- 晨露、道心连胜、护道符、里程碑、修行日历全部保留（现实日奖励层不动）

### 4.4 测验门控解绑与奖励改锚

| 项 | 现状 | 改为 |
|---|---|---|
| END_DAY 门控 | 需当日任务堂完成 | 无门控，任何时刻可推进/入定 |
| 测验资源奖励 | 每游戏日 1 次 | 每现实日 1 次（跨日 sync 重置；同日追加答题只更新 SRS 卡与统计，不发资源） |
| 打卡（道心） | QUIZ_CONFIRM 时 | 不变（本就锚现实日） |
| SRS 调度 | `realDay.today` 注入 | 不变 |

- 任务堂按钮保留（背词入口常驻），仅去掉「完成后才能结束这一天」的强制关系
- 教程/引导文案同步改（现第 1 步绑定「完成任务堂才能推进」）

### 4.5 明日预告

- 出关摘要（及手动 END_DAY 日志）尾部追加一行：从预告池（行情/灵潮/天象/后山异象）确定性抽取
- 首版只做文案钩子，不绑定真实事件触发（预告 ≠ 必然发生），池内容与抽取规则在设计文档定

## 5. 业务对象

| 对象 | 变更 |
|---|---|
| GameState.realDay | 删 `gamesToday`；`today` 保留 |
| GameState.quizDaily | 奖励锚从游戏日改现实日（字段语义调整，迁移处理） |
| LogEntry | 入定汇总条目 kind（复用 settle 或新增，设计文档定） |
| constants HERBS.days | 全表 ÷3 |
| MEDITATE 动作 | 新增 GameAction 类型 |

## 6. 边界与异常

| 场景 | 行为 |
|---|---|
| 月末未结算点入定 | 拒绝并引导先完成定额（原型已演示该态） |
| 入定中触发筑基结算 | 一次性全屏结算不入档前中断入定：先完成批量结算落盘，再展示 MilestoneScreen |
| 入定后旧档田块进度折算 | `progress × 新days/旧days` 四舍五入；已成熟保持成熟；折算后恰达成熟不丢 |
| 同现实日多场测验 | 第二场起无资源奖励，SRS 照常调度；入口有提示 |
| 时钟倒流 | 沿用 real-day.md：不回退不重置，按已存档 today 继续 |
| 多标签页 | 沿用 storage 事件机制 |

## 7. 非功能要求

- 入定批量结算与手动 END_DAY×N 逐日等价（vitest 断言等价性）
- 引擎零时间依赖不破坏：MEDITATE 与 END_DAY 一样只读状态
- 存档 v4→v5 迁移可逆性不要求，但 v4 导码可导入
- balance-sim 新增 session 口径报告（每 session 完整一茬的时长/操作次数）

## 8. 验收标准

1. 玩家可在单 session 内完成 种→入定→收→卖 完整一茬（青灵草 5 游戏日内成熟）
2. 入定 5 天与手动 END_DAY×5 的状态结果完全一致（事件序列按 rngState 推进等价）
3. 月末出关自动进入定额结算，刷新恢复后不重复扣资源
4. 地力透支全链路删除：全仓 grep 无 gamesToday/DIMINISH 残留，TopBar 无标签
5. 未完成任务堂可直接入定/结束当天；同现实日第二场测验无资源奖励
6. v4 旧档迁移后：生长中田块进度按比例折算、当日测验完成态保持、连胜/晨露/日历无损
7. 出关摘要含逐日事件/成熟/缺水与明日预告一行；入定汇总日志不超 3 条
8. sim 报告：新周期下定额达成率 ≥95%、session 一茬时长中位数 ≤10 分钟（操作次数口径）

## 9. 待确认项

| # | 问题 | 默认建议 |
|---|---|---|
| 1 | 入定跨度上限「当月末」是否放开为跨月自动缴定额 | 否——月末定额是仪式感节点，保留为唯一中断 |
| 2 | 预演是否显示逐日事件明细（现在只显示成熟/风险汇总） | 首版汇总即可，明细在出关结果 |
| 3 | 生长期 ÷3 后灵草 exp/售价是否同步调 | 由 sim 校准定；倾向 exp 不动（晋阶变快≈可接受）、售价按比例微调 |
| 4 | 「至下次成熟」快捷档当所有田已成熟时 | 置灰并提示「田已成熟，请先收获」 |

## 10. 关联任务

- T49 时间解耦与节奏压缩（TASK.md 已登记）
- 依赖无；后续批次（品阶重定义、炼丹、逐株 roll）另立任务

## 11. 实施结论（2026-11-18 交付时回填）

- §9 四个待确认项均按默认建议落地：月末唯一中断保留；预演只给汇总；exp/售价不动（sim 复核）；全田成熟时「至下次成熟」置灰
- 验收 §8 对位：1/2/3/4/5/6/7 由 vitest 163 + e2e 5 + 浏览器 smoke 13 项覆盖
- 验收 §8-8 sim 数字（500 局）：定额达成率 session1 96.8% / session2 96.6% / session3 94.0% / 轮作 96.4%；session3 差 1 个点的欠缴集中在开局前两月爬坡期（首月免罚、第 2 月 5.4%、第 3 月 3.4% 递减），判定非定额错配、数值不动；「QUOTA_TARGET 15→14 可拉平 session3」留作调参候选待拍板
- sim 口径说明：月度连推档达成率 26%~49% 系该档定义极端（整月仅一场测验资源）所致，不代表玩家可达节奏，不作为验收口径
