# 存档设计（持久化 / 导入导出 / 多标签页）

## 1. 需求追溯

- 关联需求：REQ-LINGZHIJI-001 §14（存档行）、§16.3 / §16.5（验收）、§18（多标签页风险）
- 覆盖：localStorage 读写封装、保存时机、版本与迁移、导出/导入编码与校验、损坏恢复、多标签页策略
- 未覆盖：具体字段结构（见契约草案）；界面布局（ui.md 设置弹层）

## 2. 契约引用

| 契约 | 性质 | 说明 |
|---|---|---|
| CON-LINGZHIJI-SAVE-001 | 待落地草案 | 存档数据结构 v1，字段表与校验规则见 `doc/contracts/lingzhiji/save-data.md`；阶段 1 落地为 `src/game/types.ts` 后草案 `superseded`，代码成为最终事实来源 |

## 3. 技术设计

### 3.1 读写封装（`src/game/save.ts`）

- localStorage 唯一读写点（UI 与 store 禁止直用，对齐 frontend-AGENTS.md 无后端数据口径）；键名常量 `lingzhiji.save.v1`——**键名与结构版本解耦**，结构升级不改键（避免玩家丢档），当前结构版本 SAVE_VERSION = 5
- 接口：`persist(state)` / `load(): Result<GameState>` / `exportCode(): string` / `importCode(code): Result<GameState>`
- 保存失败（隐私模式 / 容量满）：捕获后返回失败，UI toast「存档保存失败，进度暂存于本页」，游戏状态留在内存继续游玩

### 3.2 保存时机（对齐 PRD「每次有效状态变化及日结算后自动存档」）

- 每次 dispatch 成功（含白天行动、答题每题作答后）即同步 `persist`
- 新开局时所选弟子形象随游戏状态保存并参与导出和导入；旧存档缺少形象字段时继续显示原弟子立绘。
- 日终管线各步后 persist，月末 `phase='quota'`、筑基结算屏等**交互中间态也入档**，刷新后从中间态继续

### 3.3 版本与迁移

- `SaveData.version`；`load` / `importCode` 接受正整数且 ≤ 当前 SAVE_VERSION 的版本，顺序走 `migrations` 升格后校验；高于当前的版本 → 拒绝（不猜测解析）
- **v1 → v2（2026-11-15 现实日锚，已落地）**：补 `realDay`（today = 迁移时刻现实日 / gamesToday = 0）与 `streak` 全零值字段，旧进度无损、连胜从 0 起算；键名不变（§3.1）
- **v3 → v4（2026-11-17 SRS + 多题型，已落地）**：错词池与已见词一次性转 FSRS 复习卡，`wrongQueue` 清空退役
- **v4 → v5（2026-11-18 时间解耦，已落地）**：生长中田块进度按新旧生长期比例折算（`round(progress × 新days/旧days)`，恰达即置成熟）；删除 `realDay.gamesToday`；`quizDaily.done` 语义改为「本现实日已领奖励」（迁移时刻已完成则保持，当日不重复发奖）。旧生长期基准 15/20/30/35/50/60 在迁移代码内留档
- 后续结构变更继续在 `migrations: ((old) => new)[]` 顺序迁移链追加；迁移只在新版本代码中新增，旧档读入即升格后入库——该链是 M2+ 内容扩展的标准通道
- 二期境界扩展等按 PRD §5.2 要求保留已有修为、种植、资源与学习记录，不得清空进度

### 3.4 导出 / 导入（Base64 导码）

```text
导出: SaveData → JSON(UTF-8) → Base64 → 文本域展示 + 复制按钮
导入: Base64 → 解码 → JSON.parse → version 校验 → 字段校验（数值 ≥0、枚举合法、
      结构完整）→ 全部通过才覆盖现有档并重载；任一步失败保留原档并提示原因
```

- 字段校验细则（`BAD_SHAPE`）：田块编号不得重复；测验会话每题 4 个选项互不重复且包含正确释义，已答记录必须是本场题目选项之一
- 校验失败 reason 枚举：`BAD_BASE64` / `BAD_JSON` / `BAD_VERSION` / `BAD_SHAPE` / `SAVE_FAILED`，UI 逐一给出可读文案
- 导入入口为 store 层 `importSaved`：校验通过后**先写入 localStorage 落盘，成功才切换游戏状态**；落盘失败返回 `SAVE_FAILED`，当前游戏与旧存档均保持不变（设置弹层与开始画面共用该入口，导入覆盖前二次确认）
- 提示玩家自行保存导码；清除浏览器数据仍可能丢失本地存档（PRD §14 口径）

### 3.5 损坏恢复

- `load` 解析或校验失败：不覆盖、不删除原字符串（保留人工抢救机会）
- StartScreen 常驻「导入存档码」入口（弹窗粘贴导码 → 导入并继续；有存档时覆盖前确认）；存档损坏时「继续修行」失败提示可导入或重置，「重置开局」需二次确认（将清空原档）

### 3.6 多标签页（PRD §18 P1 在此明确）

- 监听 `storage` 事件（同键他页写入）：检测到时顶部显示常驻横幅
- 横幅动作：[载入最新存档]（丢弃本页内存态，重载）｜[留在此页继续]（收起横幅，本页后续操作将覆盖他页存档）
- 不做锁与合并（KISS：单机游戏，横幅 + 明确后果提示已满足验收）

## 4. 界面原型

设置弹层（完整布局见 `lingzhiji/ui.md`）：

```text
┌─ 设置 · 存档 ────────────────────────────────────┐
│ [导出存档]  ┌────────────────────────┐           │
│            │ eyJ2ZXJzaW9uIjoxLCJkYXl… │ [复制]   │
│            └────────────────────────┘           │
│ [导入存档]  ┌────────────────────────┐           │
│            │ 粘贴导码…               │ [导入]    │
│            └────────────────────────┘           │
│ （导入前确认「会覆盖当前存档」）                  │
│ ⚠ 导码无效：不是合法的灵植记存档（原档已保留）    │ ← error 态
│ ⚠ 保存失败，请保留导码并检查浏览器存储           │ ← error 态
│ [重置开局]  （二次确认后清空）                   │
└──────────────────────────────────────────────────┘
```

多标签页横幅：

```text
┌─ ⚠ 检测到其他标签页更新了存档 ────────────────────────┐
│ [载入最新存档]   [留在此页继续（之后的操作会覆盖）]    │
└──────────────────────────────────────────────────────┘
```

## 5. 交互与异常

| 场景 | 行为 |
|---|---|
| 测验中刷新 | 会话含已答记录完整入档，恢复后继续同一场不重抽（quiz.md） |
| 导码损坏 / 版本不符 | 保留原档 + 明确原因；不部分写入 |
| 导码有效但存储不可写 | 提示「保存失败，请保留导码」，当前游戏与旧档均不变（`SAVE_FAILED`） |
| 月末结算中刷新 | 恢复到 `phase='quota'` 重开弹窗（core-loop.md） |
| 保存失败反复出现 | toast 不刷屏（同类提示合并），设置弹层给出排查建议 |
| 隐私模式首次进入 | 引导文案提示本模式存档不可用，仍可试玩 |

## 6. 验证方式

- vitest：导码往返一致（state → export → import → 深比较）；四类坏导码不覆盖原档；版本不识别拒绝；中间态（测验中 / 月末 / 筑基屏）序列化恢复等价；store 导入成功后进入已保存游戏并落盘，无效导码或写入失败时保留旧档与当前游戏（recovery.test.ts）
- smoke test：PRD §16.3（白天行动后刷新、测验中刷新、导出导入一致、坏码不覆盖）
