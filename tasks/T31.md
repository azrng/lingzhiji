# T31 · 玩家旅程 e2e 固化

## 任务范围
- 将真人试玩的核心循环固化为 Playwright e2e：启动页选形象 → 入门指引 → 任务堂先学后测（满分/全错两路径）→ 领奖打卡 → 播种/浇灌/吐纳 → 坊市 → 结束一天日结算 → 次日重置
- 另覆盖测验中途刷新的存档恢复路径（save.md 每动作持久化的行为契约）
- 引擎与 UI 代码零改动，纯测试资产

## 关键决策
- **先经用户确认再引入 e2e**（frontend-AGENTS.md「视觉验收」按需能力条款）：用户在试玩过程中直接点名「你玩的过程做成代码，e2e playwright」，视为已确认；Node 栈走 npm 侧 @playwright/test@1.65.1
- 浏览器走系统 Edge（`channel: 'msedge'`），免下载 Playwright chromium（约 120MB）；换机器跑需本机装有 Edge 或改配置 + `npx playwright install chromium`
- 断言真相源选 localStorage 存档（`lingzhiji.save.v1` 的 game 字段）而非顶栏 DOM：资源数值断言不依赖 DOM 结构，顶栏仅做文案可见性断言
- 命名 `*.e2e-spec.ts`：vitest 默认 include `**/*.{test,spec}.*` 不匹配连字符形式，天然分流，vite.config 零改动；Playwright 侧 `testMatch` 精确命中
- `clickButton` 兜底封装：先常规点击（3s），超时再 force——动效环境下 actionability 校验偶发不通过（元素持续动画），force 绕过；引擎动作幂等（重复 QUIZ_NEXT 被拒）兜底误点风险

## 试玩过程中排查过的问题（均非游戏 bug）
- **测验第 1 题"未点即判错"疑点**：存档记录 answers[0]=第一个选项文本，非空。受控复现（清档 + document 级输入事件监听 + 干净流程重玩）事件流完全正常、answers[0]=null——结论：自动化后端点击重试落在已切换的新按钮上（幽灵点击），纯人工操作几乎不可能触发；引擎侧 answers[idx]!==null 幂等防护有效。e2e 的 force 点击策略即由此而来
- **顶栏"灵气+2 与文案+1 不符"疑点**：读存档实际值正确（灵气1/心得2/贡献0），真实 DOM 配对也正确——是可访问性快照的行序解读错误，TopBar 无 bug
- **开局覆盖确认**：StartScreen 有 `window.confirm` 覆盖确认（hasSave 时），自动化环境默认接受；试玩用 IAB 是隔离 webview，不影响用户日常浏览器存档
