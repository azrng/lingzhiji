# 界面结构与状态设计

## 1. 需求追溯

- 关联需求：REQ-LINGZHIJI-001 §13（UI 概述）、§16（验收路径）
- 覆盖：屏幕与弹层清单、主屏线框、开始画面、全局状态映射、新手引导、视觉与素材口径、响应式、smoke test 清单
- 未覆盖：各弹层内部交互线框（归属各功能文档）；视觉 token 取值（`design-system.yaml` 唯一事实来源）

## 2. 契约引用

无对外契约；本模块消费 `design-system.yaml`（候选值，原型确认后锁定）与 `design/concept-art/` 美术素材。

## 3. 技术设计

### 3.1 屏幕与弹层清单

| 单元 | 组件 | 归属文档 |
|---|---|---|
| 开始画面 | StartScreen | 本文档 §4.2 |
| 主屏（单屏布局） | GameScreen = TopBar + FieldGrid + ActionPanel + DayLog | 本文档 §4.1 |
| 任务堂（全屏） | QuizModal | quiz.md |
| 坊市 | MarketPanel | economy.md |
| 定额结算 | QuotaModal | economy.md |
| 设置 / 存档 | SettingsModal | save.md |
| 事件与突破提示 | EventToast | core-loop / progression.md |
| 筑基结算（全屏） | MilestoneScreen | progression.md |
| 新手引导（overlay） | TutorialOverlay | 本文档 §4.3 |

自研轻量组件（Modal / Toast / 进度条 / 按钮组），不引入组件库；视觉取值全部经 token 管线（architecture.md §7）。

### 3.2 布局基线与原型候选

- 需求基线（PRD §13）：顶部状态栏 → 中部灵田格 → 底部行动面板 + 当日日志流
- `design-system.yaml` 候选构图：日志与弟子侧边化、底部只留行动
- 两者差异在**阶段 1 HTML 原型**中定稿（frontend-AGENTS.md「原型设计与确认」）；本文档线框按需求基线绘制，原型阶段允许在该候选范围内调整，超出则回到设计文档修订

### 3.3 全局状态映射（loading / empty / error / 条件不足）

本作无权限系统，「no-permission」统一映射为**条件不足**（境界 / AP / 灵气 / 灵石 / 库存不足）：按钮保留名称、禁用并展示原因，不只降透明度（对齐 design-system 候选规范）。

| 状态 | 出现位置 | 表现 |
|---|---|---|
| loading | 启动读档、导入导码解析 | 骨架屏 / 按钮 spinner；本作数据本地，均为瞬态 |
| empty | 空田、日志无记录、仓库无可售、无存档 | 占位图示 + 一句引导（如「空田 · 点击播种」） |
| error | 存档损坏（StartScreen）、词库不可用（任务堂入口）、保存失败（toast）、导入失败（设置弹层） | 可读原因 + 恢复动作，不暴露内部实现 |
| 条件不足 | 播种 / 收获 / 开荒 / 购买 / 赎回 / 结束当天（未完成背词）等 | 按钮禁用 + 原因文案（各功能文档已给文案方向） |

### 4.3 新手引导（首次开局，3 步 overlay）

1. 「先去任务堂」：完成 10 题才能推进游戏日，答错也能继续；合格得 3 灵气可种满三块青灵草
2. 「播种的条件」：空田点击播种，弹层显示所需境界与灵气；开局可种青灵草、凝露花
3. 「首月定额免罚」：展示 15 株折算进度说明；第 2 月起未缴会扣贡献与灵石

完成标记入档（`tutorialDone`），不再重复；跳过按钮常驻。

### 3.4 视觉与素材口径

- 视觉 token：`design-system.yaml`（候选值）→ Tailwind `@theme`（`src/styles/theme.css`），界面不得硬编码取值
- 图标口径：功能图标 @ant-design/icons；灵植、资源、事件使用 `design/concept-art/` 项目素材（T8 产出）
- 视觉方向：淡雅仙侠手账风（PRD §13）；`design/mock-ui/` 为早期探索稿，仅作参考不作规范

### 3.5 响应式

- 桌面网页为主要体验（design-system 候选 ui_goal）；窄屏（<768px）保底可用：田格 2 列、行动面板与日志纵向堆叠、弹层保证关闭与确认可见可点
- 不做移动端深度适配（PRD §15 二期非目标）

## 5. 交互与异常

- 弹层互斥：全屏层（任务堂 / 筑基结算）独占；普通弹层同屏最多 1 个 + toast 不遮挡关闭与确认
- 弹层焦点与键盘（`useModalFocus`）：弹层打开即聚焦首个可交互元素，Tab / Shift+Tab 圈定在弹层内，Esc 关闭可关闭弹层（定额结算、筑基结算等强制层不响应 Esc），关闭后焦点还原到触发元素；键盘事件仅由最上层弹层（`data-game-modal`）响应；弹层统一带 `role=dialog` / `aria-modal`
- 答题区键盘流：进入题目聚焦首个选项，作答后聚焦「下一题」，作答反馈以 `role=status` 播报（quiz.md）
- `?debug=1` 调试面板：跳天 / 加资源，仅验证用，不进入常规 UI 流（core-loop.md）
- 多标签页横幅、存档导出导入、月末弹窗中断恢复见 save.md / economy.md

### 3.6 交互原型（阶段 1 已产出）

- **选型决策**：用户指定以 React 同栈直接开发原型（数据 mock），偏离 frontend-AGENTS.md 决策表「普通 Web → HTML 原型」默认行；按该规则「用户对选型另有指定时以用户指定为准，并记录在设计文档中」记录于此。理由：本作原型难点在状态循环（任务堂四相位、日推进门控、条件不足态），同栈原型的组件与交互可复用进正式实现
- **位置**：`doc/design/prototype/lingzhiji/game-proto/`（Vite 7 + React 19 + TS strict + Tailwind 4 + Zustand 5 最小工程，运行方式见其 README；素材复制于 `design/concept-art/`）
- **覆盖**：开始画面、主屏（顶栏/田格四态/行动面板/侧边日志）、任务堂全流程、坊市、月末定额、事件与突破 toast、筑基结算、设置演示桩、新手引导、调试面板（原型专用）
- **已知简化**：逻辑集中于单文件 store（正式版拆 `src/game/` 纯逻辑层）、`Math.random()`（正式版可播种 PRNG）、无持久化、导入导出为演示桩
- **布局说明**：2026-11-15 用户授权按「适合游戏的构图」定稿，采用候选构图（侧边日志）并回改 §4.1 线框，与原型一致
- **启动页更新**：2026-11-15 用户确认人物选择与启动页方案，并要求后续直接修改代码。开始画面采用山野场景衬底的左右布局，提供可爱小师妹、帅气师兄、性感师姐三种形象，所选立绘同步至游戏侧栏与筑基结算；原型已同步该方案（含侧栏头像与结算立绘）。
- **状态**：布局已定稿；其余视觉 token 待用户确认后回填 `design-system.yaml` 锁定

## 6. 验证方式（smoke test 清单，对齐 PRD §16）

1. 新开局 → 引导 3 步 → 任务堂完成 10 题（含答错）→ 确认领奖 → 结束当天
2. 播种 → 浇灌 → 灌注 → 日终事件观察 → 成熟收获 → 修为入账与顶栏更新
3. 坊市买种（含境界不足确认弹窗）→ 第 30 天定额缴纳 → 欠缴路径扣罚 → 连续两月收田 → 赎回
4. 功法进阶（心得 + 贡献）→ Lv2 生长期变化 → 累计修为至 520 → 筑基成绩单 → 继续修行
5. 刷新恢复（白天 / 测验中 / 月末）→ 导出导入往返 → 坏导码拦截 → 多标签页横幅
6. 窄屏视口走通 1–2 主路径；全部条件不足态逐一出现并展示原因
