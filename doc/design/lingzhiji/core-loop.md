# 核心循环设计（时间 / AP / 日结算 / 随机事件）

## 1. 需求追溯

- 关联需求：REQ-LINGZHIJI-001 §2（核心循环）、§4（时间系统与每日结算顺序）、§7（行动清单）、§11（随机事件）、§12（参数表）
- 覆盖：游戏日推进门控、AP 消耗、日结算管线、随机事件表与即时/持续效果、当日日志
- 未覆盖：各行动内部规则（farming / quiz / economy 文档）、境界数值（progression 文档）

## 2. 契约引用

无对外契约；`GameState` 中的日结算相关字段（`day` / `phase` / `ap` / `wateredToday` / `tunaUsedToday` / `pendingTomorrow` / `log`）定义见 CON-LINGZHIJI-SAVE-001 草案。

## 3. 技术设计

### 3.1 时间与每日状态

- `day`：1 起算整数；月份与月内日为派生值：`month = ⌈day/30⌉`、`monthDay = ((day-1) mod 30) + 1`，不单独存档
- **现实日锚（2026-11-15 新增，详见 real-day.md）**：`realDay.today`（现实日索引，日切凌晨 4 点，store 在 dispatch 前经 `clock.syncRealDay` 同步）入档；引擎零时间依赖，只读状态中的现实日字段。~~`gamesToday`~~（当日已推进游戏日数）已随 T49 时间解耦删除（2026-11-18，v5 迁移清理）
- `phase`：`'day'`（白天自由行动）| `'quota'`（月末定额结算交互中）
- 每日重置标记（在日终推进时重置）：`ap = 3`、`wateredToday = false`、`tunaUsedToday = false`；当日任务堂状态不再随游戏日重置——测验资源奖励锚现实日，跨日重置在 `clock.syncRealDay`（T49，详见 time-decouple.md §3.4）
- **入定（MEDITATE，T49 新增）**：一次推进 1~（30−当日日序）个游戏日，逐日复用 §3.3 管线，月末定额为唯一中断点；详见 time-decouple.md §3.1
- 离线不推进；调试面板 `?debug=1` 提供「跳天 / 加资源 / 跳现实日 +1」，仅验证用，正常入口不可见

### 3.2 行动分发

行动即 `GameAction`，engine 按 PRD §7 校验 AP 与各自前置：

| Action | AP | 前置要点 | 规则归属 |
|---|---|---|---|
| PLANT / WATER / HARVEST / IRRIGATE / RECLAIM | 0/1/1/0/2 | 见 farming.md | farming |
| TUNA（修炼吐纳） | 1 | 每日限 1 次；修为 +1，15% 灵光一闪额外 +1（T62） | progression |
| QUIZZ_*（进入/答题/确认结果） | 0 | 资源奖励每现实日 1 次（T49），加练不设限 | quiz |
| BUY / SELL / EMERGENCY_SEED | 0 | 见 economy.md | economy |
| GONGFA_UP | 0 | 心得 / 贡献双消耗 | quiz |
| END_DAY | 0 | 无门控（T49：不再要求任务堂完成） | 本文档 §3.3 |
| MEDITATE（入定） | 0 | phase='day' 且 跨度不越过当月末 | time-decouple.md |

- 0 AP 行动（种植 / 灌注 / 任务堂 / 坊市 / 功法）在 AP 耗尽后仍可用；AP 不足的行动按钮进入条件不足态并说明原因
- 所有行动即时生效、即时存档（save.md）

### 3.3 日结算管线（END_DAY）

```text
endDay(state):
  1. 随机事件（§3.4）：触发 1 个——概率恒 0.3（T49 删地力透支递减）；按当月灵潮调制后的权重抽取；即时类立即结算，持续类写入 pendingTomorrow
  1b. 奇遇兑现（T55，encounters.md §3.1）：昨日预掷入队的奇遇在此结算（与日常事件相互独立，可同日并存）；
      特殊/传说档兑现时置冷却，传说档留痕限次；月末（步骤 4 提前返回）前照常兑现
  2. 全田自然生长 +1 天；功法 Lv2 生长期 -1 已在常量表生效；推进后逐田检查成熟（成熟停驻，farming.md）
  3. 缺水结算：!wateredToday 且仍生长中的田 dryStreak +1；达 3 触发当茬减产（farming.md）；入定闭关豁免（T54 dryExempt）
  4. 月末判定：monthDay == 30 → phase = 'quota'，进入定额结算交互（economy.md）；
     玩家在弹窗完成缴纳/放弃后 monthSettle() 收尾
  5. 推进：day + 1，重置 ap / wateredToday / tunaUsedToday，清空消费 pendingTomorrow；任务堂状态不重置（T49：奖励锚现实日）；跨入新月（dayInMonth == 1）时记录本月灵潮日志（§3.4）+ 市场事件生效公告（T57，market-events.md，首月无事件不出）+ 刷新委托选项；dayInMonth == 15 时预掷下月市场事件并公告「坊市风声」（预告=必然）
  6. 明日预告（T49，time-decouple.md §3.6）：先掷明日奇遇入队（T55，encounters.md §3.2——预掷是「预告必兑现」的留痕），
     特殊/传说档出该 id 固定伏笔文案，普通/无走 TOMORROW_HINTS 氛围池；kind 'action' 追加日志（不弹 toast）；月末过渡不出
  7. 自动存档（含中间态：步骤 4 玩家未完成交互时，phase='quota' 直接入档，恢复后继续）
```

- T49 前 steps 1（QUIZ_NOT_DONE 门控）与事件率递减（gamesToday ≥ 1 时 0.15）已删除；END_DAY 与 MEDITATE 共用本管线（入定逐日调用，月末自动出关）

- 步骤 2–4 的顺序固定，事件先即时增减当茬产量、再处理缺水（PRD §6 产量顺序）
- 白天已收获的灵草可计入当日月末缴纳（步骤 5 在全部行动之后）

### 3.4 随机事件

- 事件表、权重与效果描述常量集中在 `constants.ts`（PRD §11：正 56 / 负 41 / 行情 1）；`EventDef.effect` 为判别联合的效果描述，`applyEvent` 是通用解释器，**新增事件只加数据条目，不改结算管线**（2026-11-15 数据化改造）
- 触发概率恒 0.3（T49 前地力透支期降 0.15 的递减已随 gamesToday 删除）
- 效果种类（`EventEffect`）：当茬产量增减（随机生长中田）、全田生长进度增减、资源增减（灵石 / 贡献 / 心得 / 灵气，灵气走 `farming.gainQi` 上限截断，其余受出口钳制）、修为入账（统一走 `gainCultivation`）、仓库随机灵草增减、持续类（灵泉 `infusionDouble`、行情 `marketMult`）
- 触发判定与目标选取（随机田 / 随机灵草）全部走 PRNG；无有效目标时按 PR §5.4「无事发生」处理，不顺延、不替换
- 即时类（灵雨 / 灵蝶 / 师姐 / 拾灵石 / 长老 / 灵兽来访 / 仙人残梦 / 灵气涌动 / 虫害 / 偷食 / 阵法波动 / 灵石失窃）在步骤 2 直接结算并入日志
- 持续类写入 `pendingTomorrow`，在**下一个游戏日**生效：
  - 灵泉涌出 → `pendingTomorrow.infusionDouble = true`：明日灌注基础效果 ×2（farming.md 计算时消费）
  - 坊市行情 → `pendingTomorrow.marketMult = 1.5 | 0.7`：明日出售单价按此折算（economy.md 消费）
- `pendingTomorrow` 在下一次日终事件判定前清空；本次事件产生的效果保留到下一日（跨月时也经过定额结算保留），效果只覆盖一日，不叠加历史。
- 事件图标：原 10 事件用 5×2 素材 sheet（`evPos`）；新增 4 事件（灵兽来访 / 仙人残梦 / 灵气涌动 / 灵石失窃，权重各 2）暂用 emoji `icon` 兜底，素材补做见 TASK.md T24
- **月度灵潮**（PRD §11.1）：`tideOf(month)` 按 6 月周期返回主题（灵雨 / 灵蝶 / 虫潮 / 悟道 / 灵泉 / 灾劫），事件抽取权重 = 基础权重 × 主题调制系数；灵潮为派生值不入档。月初（第 1 / 31 / 61…天）记录灵潮日志（kind `settle`），开局第 1 天由初始状态直接携带当日灵潮日志

### 3.5 当日日志

- 结构：`{ day, kind: 'event'|'action'|'settle'|'breakthrough', icon, title, text }`
- 环形保留最近 50 条入档；结算类条目按步骤 2→4 顺序追加，月末结算追加汇总条目

## 4. 界面原型

本模块无独立页面；完整布局见 `lingzhiji/ui.md`。此处仅约定归属本模块的两个片段：

日志流（DayLog）：

```text
┌─ 当日日志 ────────────────────────┐
│ 🌧 灵雨      全田生长 +2 天        │  ← 事件条目（icon 用项目事件素材）
│ 🌱 青灵草    3 号田生长 +1 天      │  ← 行动/结算条目
│ ⚠ 缺水      2 号田连续缺水 3 天，  │
│              当茬产量减半          │
│ （空）暂无记录，完成行动后在此显示  │  ← empty 态
└──────────────────────────────────┘
```

结束当天（T49 起无任务堂门控，任何时刻可推进）：

```text
┌─ 结束这一天 ─────────────────────────────┐
│ [结束这一天 →]  结算当日并进入次日          │
└──────────────────────────────────────────┘
```

入定弹层（T49 新增，四态中的常态与出关态）：

```text
┌─ 入定 ──────────────────────────────┐
│ 入定时长 [========●----] 7 天        │
│ 快捷：1天 3天 7天 · 至下次成熟        │
│ 1 号田 青灵草 ████░ 3/5 · 缺水1天    │
│ 出关预演：第 19 日 · ⚠ 缺水减产      │
│ [返回] [入定 7 天]                   │
└────────────────────────────────────┘
┌─ 入定 · 已出关 ─────────────────────┐
│ 一晃 7 天过去——                     │
│ 第14日 灵雨：全田+2天                │
│ 第15日 🌾 青灵草成熟（1号田）         │
│ 第16日 ⚠ 凝露花缺水减产              │
│ 🔮 明日预告：坊市风声…               │
│ [回到灵田]                           │
└────────────────────────────────────┘
```

## 5. 交互与异常

| 场景 | 行为 |
|---|---|
| 未完成任务堂点「结束这一天」 | 照常结算推进（T49：门控删除，测验奖励锚现实日，不再绑定游戏日） |
| 题目全部答错 | 确认结果后照常放行（quiz.md 奖励口径） |
| 月末结算中断（刷新/关页） | 恢复后停留在 `phase='quota'`，重新打开定额弹窗继续，当日不重复扣资源 |
| 事件无有效目标 | 日志记「无事发生」类简述，不弹错误 |
| AP 不足点击消耗类行动 | 条件不足态：按钮禁用 + 原因「行动力不足（今日剩 0/3）」 |
| 连续游玩多游戏日 | 无现实日限制亦无惩罚（T49 删地力透支）；任务堂资源奖励每现实日 1 次，同日加练只更新复习计划；生长与定额不受影响 |
| 入定中触发境界突破 | 批量结算不中断，突破日志保留在入定折叠日志中，落盘后 MilestoneScreen 照常展示 |

## 6. 验证方式

- vitest：结算顺序（事件→生长→缺水→月末→推进）；30% 触发与权重分布（固定种子统计，含灵潮调制后的有效权重）；效果解释器逐事件用例（含无目标「无事发生」）；持续效果次日生效且仅一日；月初灵潮日志与 6 月周期轮转；月末中间态存档恢复；MEDITATE≡END_DAY×N 等价与月末截断（time-decouple.md §6）
- smoke test：完成 10 题 → 结束当天 → 观察日志顺序与资源变化；入定 7 天看出关摘要/预告/日志折叠
